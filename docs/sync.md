# `ctx-lint sync`

Write your agent rules once, in `.context/rules/`, and `sync` compiles them into each agent's
native format. Every agent gets the same rules, and `sync --check` in CI keeps it that way.

```bash
ctx-lint sync --dry-run   # show the changes as diffs, write nothing
ctx-lint sync             # write the generated files
ctx-lint sync --check     # write nothing; exit 1 if anything is stale or was edited by hand
```

## Getting started

- **You already have instruction files:** `ctx-lint init --import` converts `CLAUDE.md`,
  `AGENTS.md`, Cursor, Copilot and Windsurf rules into source rules. Identical content in several
  files is imported once, and generated files are skipped, so re-running it is safe. Add
  `--split` to get one rule per `##` section instead of one rule per file.
- **Starting fresh:** `ctx-lint init` creates `.context/config.json` (with Claude and AGENTS.md
  enabled) and a starter rule in `.context/rules/general.md`.

Then run `ctx-lint sync`. From then on, edit the sources and re-run `sync`.

## Source rules

Each `.md` file under `.context/rules/` (any depth) is one rule. The path is its id:
`.context/rules/backend/api.md` is `backend/api`.

```md
---
description: API route conventions
globs: ["src/api/**/*.ts"]
---

- Validate every request body with `zod`.
- Return errors as `{ error: { code, message } }`.
```

| Frontmatter | |
|---|---|
| `description` | What the rule is about. Agents that load rules on demand use it to decide. |
| `globs` | Files the rule applies to: a list, or one comma-separated string. Without `globs`, the rule always applies. |
| `alwaysApply` | `true`: always loaded. `false` with `globs`: only for matching files. `false` with only a `description`: the agent decides. |
| `targets` | Only compile for these agents, e.g. `[claude, cursor]`. Default: every enabled target. |
| `priority` | Order in the generated files: lower first (default `0`, then by id). |

That gives three kinds of rule:

| Kind | Frontmatter | Loaded |
|---|---|---|
| **always** | no `globs` (or `alwaysApply: true`) | on every request |
| **scoped** | `globs` | when the agent works on matching files |
| **on-demand** | `alwaysApply: false` and a `description` | when the agent decides it's relevant |

Source rules are linted by `check` like any instruction file. Their links and paths resolve from
the repo root, where the compiled text ends up.

## What gets generated

| Agent (`targets.<id>`) | always | scoped | on-demand |
|---|---|---|---|
| Claude Code (`claude`) | `CLAUDE.md` | `.claude/rules/<id>.md` with `paths` | section in `CLAUDE.md` |
| AGENTS.md (`agents`) | `AGENTS.md` | section in `AGENTS.md` | section |
| Cursor (`cursor`) | `.cursor/rules/<id>.mdc`, `alwaysApply: true` | `.mdc` with `globs` | `.mdc` with `description` |
| Copilot (`copilot`) | `.github/copilot-instructions.md` | `.github/instructions/<id>.instructions.md` with `applyTo` | section |
| Windsurf / Devin (`windsurf`, off by default) | `trigger: always_on` | `trigger: glob` | `trigger: model_decision` |

Each target has layout options, for example nested `CLAUDE.md` / `AGENTS.md` files per directory
instead of separate rule files. See [configuration](configuration.md#targets).
[targets.md](targets.md) has every format detail and the vendor documentation it was checked
against.

## What `sync` will and won't touch

`sync` only writes content it generated, and it marks that content so it can tell.

- **Single files** (`CLAUDE.md`, `AGENTS.md`, `copilot-instructions.md`) get a managed block.
  Anything you write outside the markers is kept:

  ```md
  # My notes, kept as they are

  <!-- ctx-lint:begin hash=… -->
  <!-- Generated from .context/rules. Do not edit inside this block: … -->
  …generated rules…
  <!-- ctx-lint:end -->
  ```

  To choose where the block goes in an existing file, add an empty
  `<!-- ctx-lint:begin -->` / `<!-- ctx-lint:end -->` pair yourself.

- **Per-rule files** (`.claude/rules/*.md`, `.cursor/rules/*.mdc`, `*.instructions.md`) are owned
  whole and carry a header with the hash:

  ```md
  <!-- Generated by ctx-lint from .context/rules. Do not edit: … ctx-lint:hash=… -->
  ```

  A generated per-rule file whose source was deleted is deleted too. Files without the header
  are never touched.

- **Anything else** that's in the way (a hand-written `CLAUDE.md` without markers) makes `sync`
  stop with a conflict. Re-run with `--force` to overwrite it, after checking with `--dry-run`.

`sync` is all or nothing: if any source rule is invalid or any file conflicts, nothing is
written. The output has no timestamps, so running `sync` twice changes nothing the second time.

With `"mode": "file"` in the config, `sync` owns the single files whole as well (header instead of
markers).

## Hand edits

The hash covers the generated text. If someone edits it by hand:

- `ctx-lint check` warns ([generated-file-modified](rules/generated-file-modified.md)) and
  points to the source rule to change instead.
- `ctx-lint sync --check` exits 1.
- `ctx-lint sync` replaces the edit with the compiled source. Run `--dry-run` first to see it.

Problems inside generated text (a broken path, say) are reported once, on the source rule, not
again in every generated copy.

## Options

| Option | |
|---|---|
| `--dry-run` | Print the planned changes as diffs, write nothing |
| `--check` | Write nothing; exit 1 if any generated file is missing, stale or hand-edited |
| `--target <id>` | Only `claude`, `agents`, `cursor`, `copilot` or `windsurf` (repeatable) |
| `--force` | Overwrite files that weren't generated by `ctx-lint` |

Exit codes: `0` success (or up to date); `1` out of date with `--check`, a conflict, or invalid
source rules (nothing is written); `2` usage or configuration error.
